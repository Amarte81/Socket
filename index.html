Modulo 01 InetAddress • IP • Porte

1. Fondamenti di Rete, IP, Porte e Trasporto

Come due programmi Java su macchine diverse si trovano in rete tramite Indirizzo IP (la "via") e Porta (l'"interno" 0-65535), scegliendo tra canale affidabile TCP o datagrammi veloci UDP.

Approfondimento Rapido:
  • Indirizzo IP & DNS: In Java la classe InetAddress.getByName("localhost") risolve nomi simbolici in indirizzi IPv4/IPv6 (es. 127.0.0.1 per il loopback locale).
  • Porte Logiche (16 bit): Da 0 a 1023 sono Well-Known Ports (es. 80 HTTP, 443 HTTPS); per le nostre app Java usiamo porte 1024–49151 (es. 8080, 5000, 9090).
  • Socket = Coppia (IP, Porta): Una connessione TCP è identificata univocamente dalla 4-tupla (IP_Client, Porta_Client, IP_Server, Porta_Server).
Modulo 02 ServerSocket • Socket

2. Socket TCP in Java: Primo Client e Server

Creazione di una connessione orientata al flusso con java.net.ServerSocket (in ascolto sulla porta) e java.net.Socket (canale bidirezionale dedicato tra Client e Server).

Approfondimento Rapido:
  • Lato Server: Istanzia new ServerSocket(5000) e invoca Socket client = server.accept(). Il metodo accept() è bloccante: sospende il thread finché un client non completa il Three-Way Handshake TCP.
  • Lato Client: Istanzia new Socket("127.0.0.1", 5000). Il sistema operativo assegna automaticamente una porta effimera libera al client.
  • Chiusura sicura: Usa sempre il costrutto Java try-with-resources per garantire il rilascio dei descrittori di socket.
Modulo 03 Multi-Client • Thread • Runnable

3. Server Multi-Client con i Thread

Come superare il blocco del Server monothread: il meccanismo con cui il Thread principale accetta le connessioni in un ciclo while(true) e delega ogni Client a un Thread dedicato.

Approfondimento Rapido:
  • Il Problema Monothread: Se il thread main resta dentro il ciclo readLine() del Client 1, non può tornare su server.accept() e tutti gli altri Client restano in attesa!
  • Il Meccanismo Multi-Thread: Appena accept() restituisce il Socket di un nuovo Client, il main avvia un new Thread(new ClientHandler(client)).start() e torna immediatamente in ascolto su accept().
  • Dialogo Parallelo: Ogni ClientHandler gestisce e chiude il proprio Socket in modo completamente indipendente dagli altri Client.
Modulo 04 BufferedReader • Timeout • JSON

4. Stream I/O, Framing, Timeout e Serializzazione

Come leggere e scrivere testo, dati binari, oggetti Java (Serializable) e payload JSON sul socket evitando i classici blocchi infiniti (deadlock di I/O) e gestendo i timeout.

Approfondimento Rapido:
  • Catena degli Stream: socket.getInputStream() restituisce byte grezzi; lo avvolgiamo in new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8)) per leggere righe intere con readLine().
  • La Trappola di readLine(): Aspetta il carattere \n! Se chi invia usa print() invece di println() o dimentica il flush(), entrambi i lati restano bloccati per sempre.
  • Timeout di Lettura: Con socket.setSoTimeout(5000) evitiamo che un client lento o disconnesso blocchi il thread all'infinito (solleva SocketTimeoutException).
Modulo 05 ExecutorService • ConcurrentHashMap • synchronized

5. Thread Pool e Stato Condiviso Thread-Safe

Evoluzione per server di produzione: riutilizzo dei thread con ExecutorService (Thread Pool / Virtual Threads) e protezione dei dati condivisi tra più client (synchronized, ConcurrentHashMap).

Approfondimento Rapido:
  • Thread Pool vs Thread Illimitati: Creare new Thread() per 10.000 client esaurisce la RAM (OutOfMemoryError). Con Executors.newFixedThreadPool(N) o Executors.newVirtualThreadPerTaskExecutor() (Java 21+) controlliamo le risorse.
  • Thread-Safety: Se più ClientHandler modificano una struttura comune sul server (es. inventario, biglietti o mappa chiave-valore), usiamo ConcurrentHashMap, AtomicInteger o metodi synchronized.
Modulo 06 DatagramSocket • DatagramPacket

6. Programmazione UDP Senza Connessione

Quando la velocità e la bassa latenza contano più della consegna garantita: invio di pacchetti autonomi con DatagramSocket e DatagramPacket per sensori IoT, gaming e service discovery.

Approfondimento Rapido:
  • Nessun Handshake: Non esiste ServerSocket. Entrambi i lati usano DatagramSocket. Ogni DatagramPacket porta con sé l'IP e la porta del destinatario (come una cartolina postale).
  • Attenzione al Buffer: Quando ricevi in un byte[] buf = new byte[1024], devi leggere solo i byte effettivamente ricevuti tramite new String(packet.getData(), packet.getOffset(), packet.getLength())!

Tutte le operazioni di rete possono fallire per cause esterne al programma (cavo scollegato, firewall, host inesistente). Per questo il package java.net solleva eccezioni controllate (IOException, UnknownHostException). Usando try (Risorsa r = ...) { ... } (AutoCloseable), Java chiude automaticamente le risorse di rete anche in caso di eccezione.

🏢 Indirizzo IP (L'Edificio)

Identifica univocamente l'interfaccia di rete di un host (es. IPv4 192.168.1.10 o loopback locale 127.0.0.1).

IP Speciali da conoscere in Java:
  • 127.0.0.1 (localhost): Interfaccia di loopback. I pacchetti non escono sulla scheda fisica ma restano nel kernel del tuo PC. Ideale per testare Client e Server sulla stessa macchina!
  • 0.0.0.0: Sul lato Server indica di ascoltare su tutte le schede di rete del computer (Wi-Fi, Ethernet, Loopback).

🚪 Porta Logica (L'Interno)

Intero senza segno a 16 bit (0..65535) che permette al Sistema Operativo di smistare i pacchetti al processo Java corretto.

  • 0 – 1023 (Well-Known): Riservate ai servizi di sistema (80 HTTP, 443 HTTPS, 22 SSH, 53 DNS). Su Linux/macOS richiedono permessi di root.
  • 1024 – 49151 (Registered): Da usare per i nostri Server Java (es. 5000, 8080, 9000).
  • 49152 – 65535 (Ephemeral): Assegnate automaticamente dal Sistema Operativo ai Client quando aprono una connessione.

🔌 Il Concetto di Socket

Un'astrazione software che combina Indirizzo IP + Porta + Protocollo, esponendo la rete come uno stream di lettura/scrittura.

Un singolo Server sulla porta 8080 può avere migliaia di socket aperti contemporaneamente sulla stessa porta 8080 perché il sistema operativo distingue ogni connessione tramite l'intera 4-tupla: (IP_Client, Porta_Effimera_Client, IP_Server, 8080).

TCP vs UDP Layer 4 Trasporto

Scelta del Protocollo di Trasporto: TCP vs UDP in Java

A livello di trasporto (Layer 4 ISO/OSI), Java mette a disposizione due famiglie di Socket completamente diverse: Stream Socket (TCP) e Datagram Socket (UDP).

📞 TCP (Transmission Control Protocol)

  • Orientato alla connessione: Richiede il 3-Way Handshake (SYN → SYN-ACK → ACK) prima di scambiare dati.
  • Affidabile e Ordinato: I byte arrivano nello stesso ordine in cui sono stati inviati; i pacchetti persi vengono ritrasmessi automaticamente dal kernel.
  • Basato su Stream di Byte: Non conserva i confini dei singoli messaggi (serve framing esplicito, es. andare a capo \n).
  • Classi Java: ServerSocket e Socket. Usato in HTTP/REST, database, chat, microservizi.

✉️ UDP (User Datagram Protocol)

  • Senza connessione (Connectionless): Nessun handshake iniziale; spedisce subito il pacchetto.
  • Best-Effort (Non affidabile): I pacchetti possono andare persi, arrivare duplicati o fuori ordine senza avviso.
  • Basato su Messaggi (Datagrammi): Ogni pacchetto è un'unità atomica a sé stante (max ~64 KB) con destinatario IP:Porta.
  • Classi Java: DatagramSocket e DatagramPacket. Usato in streaming real-time, DNS, telemetria IoT, gaming.
💡 Analogia Pratica: Telefonata (TCP) vs Cartolina Postale (UDP)
Usare un Socket TCP è come fare una telefonata: prima componi il numero, aspetti che l'altro risponda "Pronto!" (Handshake), parli in un flusso continuo con la certezza di essere ascoltato in ordine e alla fine riagganci (close()).
Usare un Socket UDP è come imbucare una cartolina: scrivi indirizzo e porta su ogni singola cartolina e la spedisci subito senza sapere se e in quale ordine arriverà.

Guida Sintattica Pre-Esempio

La classe InetAddress rappresenta un indirizzo IP (IPv4 o IPv6) e non ha costruttori pubblici: si ottiene tramite metodi factory statici. Insieme a InetSocketAddress, costituisce la base per indirizzare qualsiasi Socket:

1. Host Locale (Loopback / Scheda LAN) InetAddress
InetAddress locale = InetAddress.getLocalHost();

Interroga il sistema operativo per ottenere l'oggetto InetAddress associato alla macchina su cui gira la JVM.
• locale.getHostName() restituisce il nome simbolico del computer (es. DESKTOP-PC).
• locale.getHostAddress() restituisce la stringa dell'indirizzo IP (es. 192.168.1.15).

2. Risoluzione DNS di un Dominio o IP DNS Lookup
InetAddress remoto = InetAddress.getByName("example.com");

Contatta il server DNS configurato nel sistema per tradurre un nome di dominio (es. "example.com" o "localhost") nel corrispondente indirizzo IP numerico. Se il dominio non esiste o la rete è assente, solleva UnknownHostException.

3. Test di Raggiungibilità (Ping / TCP 7) Timeout in ms
boolean attivo = remoto.isReachable(2000);

Verifica se l'host remoto risponde entro il tempo massimo specificato in millisecondi (es. 2000 ms = 2 secondi). La JVM tenta un ICMP Echo Request (ping) o una connessione TCP sulla porta 7 (Echo). Ritorna true se l'host risponde, false altrimenti.

4. Endpoint Completo (Coppia IP + Porta) SocketAddress
InetSocketAddress endpoint = new InetSocketAddress(remoto, 443);

Combina in un unico oggetto un indirizzo IP (o hostname stringa, es. new InetSocketAddress("127.0.0.1", p)) e un numero di porta TCP/UDP (0–65535).
• endpoint.getAddress() estrae l'InetAddress.
• endpoint.getPort() estrae il numero intero della porta (es. 443).

5. Connessione Socket con Timeout Esplicito Usato nell'Esercizio 1
Socket s = new Socket(); s.connect(endpoint, 200); // timeout 200 ms

A differenza di new Socket(host, port) che attende il timeout di sistema (anche 20–30 secondi!), creare un new Socket() "vuoto" e invocare s.connect(endpoint, timeoutMs) permette di interrompere il tentativo dopo pochi millisecondi se la porta è chiusa o filtrata.

6. Gestione Eccezioni di Rete java.io / java.net
catch (UnknownHostException e) { ... } catch (IOException e) { ... }

Tutte le operazioni di rete sono soggette a errori fisici o logici (cavo scollegato, DNS irraggiungibile, porta chiusa/rifiutata con ConnectException o scadenza con SocketTimeoutException). Per questo il compilatore Java obbliga a gestirle con blocchi try-catch.

Esempio 1: NetworkInspector.java java.net.InetAddress & InetSocketAddress 
import java.net.InetAddress;
import java.net.InetSocketAddress;
import java.net.UnknownHostException;

public class NetworkInspector {
    public static void main(String[] args) {
        try {
            // 1. Indirizzo della macchina locale
            InetAddress locale = InetAddress.getLocalHost();
            System.out.println("Host locale: " + locale.getHostName());
            System.out.println("IP locale  : " + locale.getHostAddress());

            // 2. Risoluzione DNS di un dominio pubblico
            InetAddress remoto = InetAddress.getByName("example.com");
            System.out.println("IP example : " + remoto.getHostAddress());
            System.out.println("Raggiungibile (2s): " + remoto.isReachable(2000));

            // 3. Creazione di un Socket Endpoint (IP + Porta 443 HTTPS)
            InetSocketAddress endpoint = new InetSocketAddress(remoto, 443);
            System.out.println("Endpoint   : " + endpoint.getAddress() + ":" + endpoint.getPort());

        } catch (UnknownHostException e) {
            System.err.println("Impossibile risolvere il nome DNS: " + e.getMessage());
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

Soluzione Esercizio 1: LocalPortScanner.javaJava SE
import java.io.IOException;
import java.net.*;

public class LocalPortScanner {
    public static void main(String[] args) throws UnknownHostException {
        // 1. Risoluzione DNS di "localhost"
        InetAddress host = InetAddress.getByName("localhost");
        // 2. Porte da controllare
        int[] porte = {22, 80, 443, 3306, 5000, 8080};

        System.out.println("Scansione su " + host.getHostAddress() + "...");
        for (int p : porte) {
            // 3. Socket "vuoto" + connect con timeout, chiuso in automatico
            try (Socket s = new Socket()) {
                s.connect(new InetSocketAddress(host, p), 200);
                // 4a. Connessione riuscita: c'è un servizio in ascolto
                System.out.println("[APERTA] Porta " + p + " (porta locale effimera: " + s.getLocalPort() + ")");
            } catch (IOException e) {
                // 4b. ConnectException o SocketTimeoutException: porta chiusa/filtrata
                System.out.println("[CHIUSA] Porta " + p);
            }
        }
    }
}

Il Meccanismo Client-Server TCP: ServerSocket vs Socket

In Java c'è una distinzione netta: il ServerSocket è il "centralinista" che attende nuove chiamate sulla porta pubblica, mentre il Socket restituito da accept() è la "cornetta dedicata" per parlare con quello specifico client.

📘 Le Nuove Istruzioni Java per Stabilire e Gestire la Connessione

Prima di avviare la simulazione interattiva, analizziamo una per una le 6 nuove istruzioni fondamentali del package java.net e java.io che useremo lato Server e lato Client:

1. Lato Server • Apertura Porta Costruttore
ServerSocket server = new ServerSocket(5000);

Ordina al Sistema Operativo di riservare la porta TCP 5000 (operazione di Bind) e di metterla in ascolto di richieste di connessione (Listen). Non blocca il programma, ma prepara il centralino.

• Se la porta 5000 è già occupata da un altro processo, lancia subito java.net.BindException: Address already in use.
• Passando new ServerSocket(0) il Sistema Operativo sceglie automaticamente una porta libera qualsiasi.
2. Lato Server • Attesa Connessione Metodo Bloccante
Socket client = server.accept();

Mette in pausa (blocca) il thread del Server finché un Client non si connette. Appena la connessione è stabilita, restituisce un nuovo oggetto Socket dedicato a quel Client.

• Il ServerSocket originale non trasporta mai dati! Serve solo ad accettare nuovi arrivi.
• Tutta la comunicazione di lettura/scrittura avviene sull'oggetto Socket client restituito da accept().
3. Lato Client • Chiamata al Server Handshake TCP
Socket socket = new Socket("127.0.0.1", 5000);

Avvia attivamente la connessione verso l'IP ("127.0.0.1") e la porta (5000) del Server, scatenando il 3-Way Handshake TCP e sbloccando la accept() del Server!

• Il Client non specifica la propria porta: il Sistema Operativo gli assegna in automatico una porta effimera libera (es. 54321).
• Se il Server è spento o la porta è errata, solleva java.net.ConnectException: Connection refused.
4. Entrambi i Lati • Flusso di Lettura Input Stream
socket.getInputStream() → in.readLine()

getInputStream() ottiene il canale dei byte in ingresso dalla rete. Avvolgendolo in BufferedReader e InputStreamReader, possiamo usare in.readLine() per leggere una riga di testo intera.

• Anche in.readLine() è bloccante: attende finché dall'altra parte del cavo non arriva il carattere di fine riga \n.
• Restituisce null se l'altro lato ha chiuso la connessione.
5. Entrambi i Lati • Flusso di Scrittura Output Stream
new PrintWriter(socket.getOutputStream(), true)

getOutputStream() ottiene il canale di invio verso la rete. Con PrintWriter(..., true) possiamo inviare stringhe usando out.println("...") con invio immediato (autoFlush).

• Il secondo parametro true attiva l'autoFlush: ogni volta che chiami println(), Java aggiunge \n e spedisce immediatamente i byte sulla scheda di rete senza trattenerli nel buffer in RAM.
6. Entrambi i Lati • Chiusura Connessione AutoCloseable
try (Socket s = ...) { ... } // chiama s.close()

Chiude gli stream e il socket scambiando i pacchetti TCP FIN / ACK e liberando le risorse del Sistema Operativo. Con try (...) la chiusura è automatica.

• Chiudere il Socket client termina solo la conversazione con quel singolo utente.
• Chiudere il ServerSocket server spegne invece l'intero servizio sulla porta 5000.

Livello 2: Modulo 2 — Perché ServerSocket.accept() restituisce un nuovo Socket?
Nel Modulo 2 abbiamo visto che ServerSocket (es. porta 5000) serve solo ad accogliere le nuove connessioni. Appena un Client completa l'handshake, accept() restituisce un oggetto Socket dedicato esclusivamente a quel Client, lasciando la ServerSocket libera di ricevere altri Client.

1. Il Problema del Server Sequenziale e il Meccanismo "Centralinista + Operatori"

🛑
Il Collo di Bottiglia del Server Monothread (Modulo 2)
Un solo Thread fa tutto

Nel Server del Modulo 2 esiste un solo flusso di esecuzione (il Thread main). Se il Client 1 si connette e impiega 3 minuti a inviare i suoi dati:

  • Il Thread main entra nel ciclo di lettura (readLine()) del Client 1 e resta bloccato lì.
  • Se nel frattempo arriva il Client 2, nessuno esegue più serverSocket.accept()!
  • Il Client 2 rimane congelato in sala d'attesa finché il Client 1 non ha finito e chiuso la connessione.
🧵
Il Meccanismo Multi-Thread: Divisione dei Ruoli
1 Dispatcher + N Thread Worker

Per servire più Client contemporaneamente separiamo nettamente chi accoglie le connessioni da chi conversa con i singoli Client:

  • Il Centralinista (Thread main): Presidia in un ciclo continuo la porta ServerSocket (accept()). Non legge e non scrive mai messaggi!
  • Passaggio di Consegna: Appena accept() produce il Socket per il nuovo Client, il main crea un Thread Worker dedicato, gli consegna quel Socket e torna subito su accept().
  • Gli Operatori Dedicati (Thread-1, Thread-2, ...): Ogni Thread Worker gestisce in parallelo la conversazione e la chiusura del proprio Socket, senza bloccare né il main né gli altri Client.

2. Dal Meccanismo al Codice Java: Le 4 Regole Costruttive
Ora traduciamo l'animazione in istruzioni Java

Ora che abbiamo visto come funziona il meccanismo nell'animazione qui sopra, vediamo come si traduce esattamente in Java. Servono 4 elementi chiave:

① Il Ciclo Infinito del Centralinista (nel main)

Nel main racchiudiamo serverSocket.accept() dentro un ciclo while (true). Appena accept() restituisce il clientSocket, il main non apre gli stream ma lo passa subito a un nuovo Thread: 

while (true) {
    Socket clientSocket = serverSocket.accept(); // Fase 2
    ClientHandler task = new ClientHandler(clientSocket);
    new Thread(task).start(); // Fase 3: delega e riparte!
}
② La Classe Operatore (implements Runnable)

Creiamo una classe ClientHandler implements Runnable con un attributo private final Socket clientSocket; passato al costruttore. Così ogni Thread Worker conserva il proprio Socket: 

class ClientHandler implements Runnable {
    private final Socket clientSocket;
    public ClientHandler(Socket socket) {
        this.clientSocket = socket; // Riceve la "pratica"
    }
    @Override
    public void run() { /* Dialogo col Client */ }
}
③ Avvio Parallelo con .start() (Mai .run()!)

L'istruzione new Thread(task).start() chiede alla JVM di creare uno stack di esecuzione separato e invocare run() in parallelo, restituendo immediatamente il controllo al main.
⚠️ Se scrivessi per errore task.run(), il codice verrebbe eseguito dentro il Thread main bloccando tutti gli altri Client!

④ Dove si chiude il clientSocket? Dentro run()!

Attenzione: Nel main non bisogna usare try (Socket clientSocket = serverSocket.accept()), altrimenti il main chiuderebbe il socket un istante dopo aver lanciato il Thread! Il blocco try-with-resources sul clientSocket e sugli stream va messo dentro il metodo run() del ClientHandler.

Mettiamo insieme i pezzi visti nel meccanismo: a sinistra il Server Multi-Thread con la classe ClientHandler, a destra un Client Interattivo che permette di inviare più messaggi da tastiera fino al comando ESCI (così puoi aprire più terminali Client contemporaneamente!).

MultiClientEchoServer.java (Server Multi-Thread)
import java.io.*;
import java.net.*;

public class MultiClientEchoServer {
    private static final int PORT = 5000;

    public static void main(String[] args) {
        int clientCounter = 0;
        System.out.println("[MAIN] Server avviato sulla porta " + PORT);

        // Il main apre SOLO la ServerSocket
        try (ServerSocket serverSocket = new ServerSocket(PORT)) {

            // 1. Ciclo infinito del Centralinista (Dispatcher)
            while (true) {
                Socket clientSocket = serverSocket.accept();
                clientCounter++;

                // 2. Crea il compito passando il Socket dedicato
                ClientHandler handler = new ClientHandler(clientSocket, clientCounter);

                // 3. Crea e avvia il Thread Worker in parallelo
                Thread worker = new Thread(handler, "Worker-Client-" + clientCounter);
                worker.start();
                // Il main torna SUBITO su accept() per il prossimo Client!
            }
        } catch (IOException e) {
            System.err.println("[MAIN] Errore ServerSocket: " + e.getMessage());
        }
    }
}

// 4. Classe Operatore eseguita da ciascun Thread Worker
class ClientHandler implements Runnable {
    private final Socket clientSocket;
    private final int clientId;

    public ClientHandler(Socket socket, int id) {
        this.clientSocket = socket;
        this.clientId = id;
    }

    @Override
    public void run() {
        String threadName = Thread.currentThread().getName();
        System.out.println("[" + threadName + "] Inizio gestione Client #" + clientId
                + " (" + clientSocket.getRemoteSocketAddress() + ")");

        // Il try-with-resources chiude clientSocket e stream a fine run()!
        try (
            Socket autoCloseSocket = this.clientSocket;
            BufferedReader in = new BufferedReader(
                    new InputStreamReader(autoCloseSocket.getInputStream()));
            PrintWriter out = new PrintWriter(autoCloseSocket.getOutputStream(), true)
        ) {
            out.println("BENVENUTO Client #" + clientId + "! Scrivi messaggi o 'ESCI' per chiudere.");

            String msg;
            // Legge più righe finché il Client non scrive ESCI o chiude
            while ((msg = in.readLine()) != null) {
                if (msg.equalsIgnoreCase("ESCI")) {
                    out.println("ARRIVEDERCI Client #" + clientId + "!");
                    break;
                }
                System.out.println("[" + threadName + "] Ricevuto: " + msg);
                out.println("ECHO da " + threadName + ": " + msg.toUpperCase());
            }
        } catch (IOException e) {
            System.err.println("[" + threadName + "] Errore I/O: " + e.getMessage());
        }
        System.out.println("[" + threadName + "] Client #" + clientId + " disconnesso. Thread terminato.");
    }
}

Soluzione: MultiClientCommandServer.java
import java.io.*;
import java.net.*;

public class MultiClientCommandServer {
    public static void main(String[] args) {
        int clientCount = 0;
        System.out.println("Command Server Multi-Client attivo sulla porta 6000...");

        try (ServerSocket serverSocket = new ServerSocket(6000)) {
            while (true) {
                Socket clientSocket = serverSocket.accept();
                clientCount++;
                Thread t = new Thread(
                    new CommandClientHandler(clientSocket, clientCount),
                    "Worker-" + clientCount
                );
                t.start();
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

class CommandClientHandler implements Runnable {
    private final Socket clientSocket;
    private final int clientId;

    public CommandClientHandler(Socket socket, int id) {
        this.clientSocket = socket;
        this.clientId = id;
    }

    @Override
    public void run() {
        String tName = Thread.currentThread().getName();
        try (
            Socket s = this.clientSocket;
            BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream()));
            PrintWriter out = new PrintWriter(s.getOutputStream(), true)
        ) {
            out.println("Connesso! Comandi disponibili: CHI_SONO | SOMMA a b | FINE");
            String line;
            while ((line = in.readLine()) != null) {
                String trimmed = line.trim();
                if (trimmed.equalsIgnoreCase("FINE")) {
                    out.println("Chiusura sessione Client #" + clientId);
                    break;
                } else if (trimmed.equalsIgnoreCase("CHI_SONO")) {
                    out.println("Sei il Client #" + clientId + " servito dal thread ["
                            + tName + "] (tua porta: " + s.getPort() + ")");
                } else if (trimmed.toUpperCase().startsWith("SOMMA ")) {
                    String[] parts = trimmed.split("\\s+");
                    int a = Integer.parseInt(parts[1]);
                    int b = Integer.parseInt(parts[2]);
                    out.println("RISULTATO: " + (a + b));
                } else {
                    out.println("ERRORE: Comando non riconosciuto");
                }
            }
        } catch (Exception e) {
            System.err.println("[" + tName + "] Errore: " + e.getMessage());
        }
    }
}

Le Insidie degli Stream su Socket: Framing, Flush e Timeout

L'errore più frequente nella programmazione Socket in Java non è un errore di compilazione, ma un blocco infinito (Deadlock di I/O) in cui sia il Client sia il Thread Worker del Server restano fermi su readLine() aspettandosi a vicenda.

⛓️ Accesso a Cascata agli Argomenti Precedenti (Modulo 3 → Modulo 2 → Modulo 1) ▼ Espandi Catena
Livello 3: Modulo 3 — Ogni ClientHandler gestisce gli Stream del proprio Socket
Nel Server Multi-Client (Modulo 3), se un Client si blocca o non invia il ritorno a capo \n, il relativo Thread Worker resta bloccato all'infinito su readLine() consumando risorse della JVM!
Livello 2: Modulo 2 — Socket.getInputStream() e Socket.getOutputStream()
Un Socket espone due flussi monodirezionali di byte grezzi: InputStream (dati in ingresso dalla scheda di rete) e OutputStream (buffer in uscita verso il kernel).
Livello 1: Modulo 1 — Natura Stream-Oriented del TCP
Il TCP non sa cosa sia un "messaggio": trasporta una sequenza continua di byte. Se il Client fa due write() da 50 byte, il Server potrebbe leggere 100 byte in una sola read() oppure 20 byte + 80 byte!

⚠️ 1. Il Blocco di readLine()

BufferedReader.readLine() non ritorna finché non vede \n, \r\n o la chiusura del socket.

Se il mittente scrive out.print("CIAO") (senza ln!), i 4 byte arrivano al destinatario, ma readLine() continua ad aspettare l'invio a capo!
Regola d'oro: Usa sempre out.println(...) oppure invia esplicitamente \n.

🚰 2. Il Buffer Non Svuotato (Flush)

BufferedWriter e PrintWriter accumulano i dati in RAM (es. 8 KB) prima di inviarli alla scheda di rete.

Se invii un piccolo comando di 10 byte senza svuotare il buffer, i byte restano nella RAM del mittente!
Regola d'oro: Passa true al costruttore new PrintWriter(outStream, true) oppure invoca manualmente out.flush() dopo ogni messaggio.

⏱️ 3. Timeout di Lettura (SO_TIMEOUT)

Cosa succede se il cavo di rete si stacca o il client/server remoto si blocca prima di rispondere?

Di default una read() su Socket aspetta all'infinito! Impostando socket.setSoTimeout(3000); (3 secondi), se non arriva alcun byte entro 3000 ms viene lanciata java.net.SocketTimeoutException, ma il socket rimane aperto e valido per riprovare o chiudere con grazia.

DataOutputStream ObjectOutputStream & JSON

Trasferire Numeri, File Binari, Oggetti Java e JSON su Socket

Non tutto è testo semplice: ecco i 3 modi professionali per inviare dati strutturati o file binari su un Socket in Java.

1. DataInputStream / DataOutputStream

Ideale per tipi primitivi (writeInt, writeDouble, writeUTF) e per il Length-Prefix Framing (invii prima la dimensione in byte del file con writeLong(size), seguita dai byte del file).

2. ObjectOutputStream (Serializable)

Serializzazione nativa Java: trasforma un intero oggetto Java (che implementa Serializable) in byte con writeObject(obj) e lo ricostruisce con readObject(). Attenzione: funziona solo se sia Client che Server sono scritti in Java!

3. Testo Strutturato JSON su UTF-8

Lo standard universale per i Microservizi: serializzi l'oggetto in una stringa JSON su singola riga (o con header Content-Length) così qualsiasi linguaggio (Java, Python, Go, JS) può comunicare col tuo Socket.

// --- LATO CLIENT: Imposta Timeout di 3 secondi e invia dati tipizzati ---
try (Socket socket = new Socket("127.0.0.1", 6000)) {
    socket.setSoTimeout(3000); // Evita blocchi infiniti se il server non risponde entro 3s!

    DataOutputStream out = new DataOutputStream(new BufferedOutputStream(socket.getOutputStream()));
    DataInputStream in = new DataInputStream(new BufferedInputStream(socket.getInputStream()));

    out.writeUTF("LAPTOP-PRO"); // Stringa con prefisso di lunghezza automatico
    out.writeInt(3);            // 4 byte int (quantità)
    out.writeDouble(899.50);    // 8 byte double (prezzo unitario)
    out.flush();                // FONDAMENTALE con BufferedOutputStream!

    double totaleConIva = in.readDouble();
    System.out.println("Totale calcolato dal server: € " + totaleConIva);
} catch (SocketTimeoutException e) {
    System.err.println("Il server ha impiegato più di 3 secondi a rispondere!");
}

Traccia: Scrivi il metodo lato Server che riceve un pacchetto binario inviato tramite DataOutputStream così formato:
1. Un int lunghezza (tra 1 e 4096 byte).
2. Un array di byte[] payload di esattamente lunghezza byte (letti tutti con in.readFully(payload)!).
3. Imposta sul socket del client accettato un timeout di lettura di 4000 ms (client.setSoTimeout(4000)).
4. Calcola la somma di tutti i byte ricevuti e rispondi al client con out.writeUTF("ACK:" + lunghezza + ":SUM=" + somma) ricordandoti il flush()!

Suggerimento: Non usare in.read(payload) perché su una rete reale potrebbe leggere solo una parte dei byte arrivati finora! Usa invece in.readFully(payload) di DataInputStream, che attende finché tutti gli N byte non sono stati riempiti nel buffer.

Soluzione Esercizio 4: BinaryFrameServer.javaLength-Prefix Framing + Timeout
import java.io.*;
import java.net.*;

public class BinaryFrameServer {
    public static void main(String[] args) throws IOException {
        try (ServerSocket server = new ServerSocket(6000)) {
            try (Socket client = server.accept()) {
                // 1. Imposta il timeout di lettura a 4 secondi
                client.setSoTimeout(4000);

                DataInputStream in = new DataInputStream(new BufferedInputStream(client.getInputStream()));
                DataOutputStream out = new DataOutputStream(new BufferedOutputStream(client.getOutputStream()));

                // 2. Legge l'header di lunghezza e valida i limiti
                int length = in.readInt();
                if (length <= 0 || length > 4096) {
                    out.writeUTF("ERR:INVALID_LENGTH");
                    out.flush();
                    return;
                }

                // 3. Legge esattamente 'length' byte dal flusso TCP
                byte[] payload = new byte[length];
                in.readFully(payload);

                // 4. Calcola il checksum semplice e invia l'ACK
                long sum = 0;
                for (byte b : payload) {
                    sum += (b & 0xFF);
                }

                out.writeUTF("ACK:" + length + ":SUM=" + sum);
                out.flush(); // Indispensabile per svuotare il BufferedOutputStream
            } catch (SocketTimeoutException e) {
                System.err.println("Client troppo lento: timeout di 4s scaduto!");
            }
        }
    }
}

import java.net.*;
import java.util.concurrent.*;

public class ConcurrentKvServer {
    // Struttura dati CONDIVISA tra tutti i thread: usare ConcurrentHashMap (MAI HashMap normale!)
    private static final ConcurrentHashMap<String, String> store = new ConcurrentHashMap<>();

    public static void main(String[] args) {
        // Pool di 20 thread worker riutilizzabili (in Java 21+: Executors.newVirtualThreadPerTaskExecutor())
        ExecutorService pool = Executors.newFixedThreadPool(20);

        try (ServerSocket server = new ServerSocket(7000)) {
            System.out.println("KV Server Multithread attivo su :7000");

                Socket clientSocket = server.accept(); // Accetta e delega subito al pool
                pool.execute(new ClientHandler(clientSocket));
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            pool.shutdown();
        }
    }

    // Task Runnable eseguito in parallelo da un thread del pool
    private static class ClientHandler implements Runnable {
        private final Socket socket;

        public ClientHandler(Socket socket) { this.socket = socket; }

        @Override
        public void run() {
            // Il worker è responsabile della chiusura del proprio Socket!
            try (socket;
                 BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
                 PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {

                    String cmd = parts[0].toUpperCase();

                        out.println("OK Salvato [" + parts[1] + "] sul thread " + Thread.currentThread().getName());
                    } else if (cmd.equals("GET") && parts.length >= 2) {
                        out.println("VALUE " + store.getOrDefault(parts[1], "NULL"));
                    } else if (cmd.equals("QUIT")) {
                        out.println("BYE");
                        break;
                    }
                }
            } catch (IOException e) {
                System.err.println("Connessione chiusa: " + e.getMessage());
            }
        }
    }

import java.io.*;
import java.net.*;
import java.util.concurrent.*;

public class TicketBookingServer {
    private static int bigliettiDisponibili = 100;

    // Metodo synchronized: previene Race Condition tra più ClientHandler simultanei
    public static synchronized String prenotaBiglietti(int n) {
        if (n <= 0) return "400 ERR Quantità non valida";
        if (bigliettiDisponibili >= n) {
            bigliettiDisponibili -= n;
            return "200 OK Prenotati " + n + " biglietti. Rimanenti: " + bigliettiDisponibili;
        }
        return "409 ERR Biglietti insufficienti! Rimanenti: " + bigliettiDisponibili;
    }

        return bigliettiDisponibili;
    }

    public static void main(String[] args) throws IOException {
        ExecutorService pool = Executors.newFixedThreadPool(16);
        try (ServerSocket server = new ServerSocket(7070)) {
            while (true) {
                Socket client = server.accept();
                pool.execute(() -> gestisciClient(client));
            }
        }
    }

    private static void gestisciClient(Socket client) {
        try (client;
             BufferedReader in = new BufferedReader(new InputStreamReader(client.getInputStream()));
             PrintWriter out = new PrintWriter(client.getOutputStream(), true)) {

            client.setSoTimeout(15000);
            String cmd;

                    out.println("200 BYE");
                    break;
                }
            }
        } catch (IOException ignored) {}
    }

In UDP non esiste un canale permanente né uno stream: ogni DatagramPacket è una "busta" indipendente che contiene l'array di byte dei dati e l'indirizzo IP:Porta del destinatario (in invio) o del mittente (in ricezione).

📦 Costruire un DatagramPacket per Inviare vs Ricevere

Il costruttore di DatagramPacket cambia forma a seconda che il pacchetto serva a ricevere dati dalla rete o a spedirli!

1. Pacchetto per RICEVERE (vuoto, senza IP):
byte[] buf = new byte[1024];
DatagramPacket inPkt = new DatagramPacket(buf, buf.length);
Quando socket.receive(inPkt) termina, Java riempie automaticamente dentro inPkt sia i byte ricevuti sia l'IP (inPkt.getAddress()) e la porta (inPkt.getPort()) di chi lo ha spedito!

2. Pacchetto per INVIARE (con IP e Porta destinatario):
byte[] data = msg.getBytes(StandardCharsets.UTF_8);
DatagramPacket outPkt = new DatagramPacket(data, data.length, destIp, destPort);

Se il tuo buffer è lungo 1024 byte ma il client invia "CIAO" (4 byte), gli altri 1020 byte contengono zeri o vecchi dati!

                           + "Connection: close\r\n\r\n";

            rawOut.write(bodyBytes);
            rawOut.flush();

In un'architettura a Microservizi, l'applicazione non è più un singolo grande Server monolitico, ma una squadra di piccoli processi Server indipendenti (es. CatalogService, OrderService, PaymentService) che comunicano tra loro tramite la rete!

1. Da Modulo 7 (Protocolli & HTTP/REST): Comunicazione Inter-Servizio
Ogni microservizio è contemporaneamente un Server (accetta richieste dall'API Gateway) e un Client (apre un Socket/HTTP verso altri microservizi per completare un'operazione).
2. Da Modulo 3 e Modulo 5 (Thread Worker & Thread Pool): Isolamento e Health-Check in Background
Ogni microservizio gestisce le richieste con ClientHandler ed ExecutorService, mentre il Registry/Gateway usa uno ScheduledExecutorService in background per verificare che i nodi siano vivi.
3. Da Modulo 4 (Timeout setSoTimeout): Prevenire i Cascading Failures (Circuit Breaker)
Se OrderService chiama InventoryService senza setSoTimeout() e InventoryService è bloccato, tutti i thread di OrderService si bloccheranno a catena! Il timeout sul socket è la base del Circuit Breaker.

🧭 1. Service Registry & Discovery

Come fa l'OrderService a sapere su quale IP e Porta gira oggi l'InventoryService?

Invece di scrivere porte fisse nel codice, creiamo un Service Registry (es. sulla porta 9000):
  • All'avvio, ogni microservizio invia al Registry: REGISTER inventory 127.0.0.1 8081.
  • Chi deve chiamare inventory chiede al Registry: DISCOVER inventory e ottiene l'elenco degli endpoint attivi!

🚪 2. API Gateway & Load Balancing

Il Client esterno non contatta mai i singoli microservizi direttamente, ma parla con un unico punto d'ingresso: l'API Gateway.

Se avviamo 2 istanze di CatalogService sulle porte 8081 e 8082, l'API Gateway (porta 8080) usa un contatore atomico (AtomicInteger) per inoltrare la prima richiesta a 8081, la seconda a 8082, la terza a 8081 (Round-Robin Load Balancing), raddoppiando la capacità!

import java.io.*;
import java.net.*;
import java.util.*;
import java.util.concurrent.*;

public class ServiceRegistry {
    // Mappa Thread-Safe: NomeServizio -> Lista di Endpoint ("127.0.0.1:8081", "127.0.0.1:8082")
    private static final ConcurrentHashMap<String, CopyOnWriteArrayList<String>> registry = new ConcurrentHashMap<>();

    public static void main(String[] args) throws IOException {
        ExecutorService pool = Executors.newCachedThreadPool();
        try (ServerSocket server = new ServerSocket(9000)) {
            System.out.println("[ServiceRegistry] In ascolto su :9000");
            while (true) {
                Socket client = server.accept();
                pool.execute(() -> handleRegistryRequest(client));
            }
        }
    }

    private static void handleRegistryRequest(Socket s) {
        try (s;
             BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream()));
             PrintWriter out = new PrintWriter(s.getOutputStream(), true)) {

            String line = in.readLine();
            if (line == null) return;
            String[] parts = line.split(" ");

            // Comando: REGISTER <serviceName> <host:port>
            if ("REGISTER".equalsIgnoreCase(parts[0]) && parts.length == 3) {
                registry.computeIfAbsent(parts[1], k -> new CopyOnWriteArrayList<>()).addIfAbsent(parts[2]);
                System.out.println("[Registry] Registrato " + parts[1] + " -> " + parts[2]);
                out.println("200 REGISTERED");
            }
            // Comando: DISCOVER <serviceName> -> restituisce lista separata da virgola
            else if ("DISCOVER".equalsIgnoreCase(parts[0]) && parts.length == 2) {
                List<String> endpoints = registry.getOrDefault(parts[1], new CopyOnWriteArrayList<>());
                out.println(endpoints.isEmpty() ? "404 NONE" : String.join(",", endpoints));
            }
        } catch (IOException ignored) {}
    }
}
import java.io.*;
import java.net.*;
import java.util.concurrent.*;

public class InventoryMicroservice {
    public static void main(String[] args) throws IOException {
        // Puoi avviare più istanze passando la porta da riga di comando (es. 8081, 8082)
        int myPort = args.length > 0 ? Integer.parseInt(args[0]) : 8081;

        // 1. Auto-registrazione presso il ServiceRegistry (:9000) come Client Socket!
        try (Socket reg = new Socket("127.0.0.1", 9000);
             PrintWriter out = new PrintWriter(reg.getOutputStream(), true);
             BufferedReader in = new BufferedReader(new InputStreamReader(reg.getInputStream()))) {
            out.println("REGISTER inventory 127.0.0.1:" + myPort);
            System.out.println("[Inventory:" + myPort + "] Risposta Registry: " + in.readLine());
        }

        // 2. Si mette in ascolto delle richieste provenienti dall'API Gateway
        ExecutorService pool = Executors.newFixedThreadPool(8);
        try (ServerSocket server = new ServerSocket(myPort)) {
            while (true) {
                Socket client = server.accept();
                pool.execute(() -> {
                    try (client;
                         BufferedReader in = new BufferedReader(new InputStreamReader(client.getInputStream()));
                         PrintWriter out = new PrintWriter(client.getOutputStream(), true)) {
                        String req = in.readLine();
                        if ("PING".equals(req)) {
                            out.println("PONG");
                        } else {
                            out.println("{\"service\":\"inventory\",\"instancePort\":" + myPort + ",\"stock\":42,\"query\":\"" + req + "\"}");
                        }
                    } catch (IOException ignored) {}
                });
            }
        }
    }
}
import java.io.*;
import java.net.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ApiGateway {
    private static final AtomicInteger rrCounter = new AtomicInteger(0);

    public static void main(String[] args) throws IOException {
        ExecutorService pool = Executors.newFixedThreadPool(16);
        try (ServerSocket gateway = new ServerSocket(8080)) {
            System.out.println("[ApiGateway] Attivo sulla porta :8080");
            while (true) {
                Socket client = gateway.accept();
                pool.execute(() -> routeRequest(client));
            }
        }
    }

    private static void routeRequest(Socket client) {
        try (client;
             BufferedReader cIn = new BufferedReader(new InputStreamReader(client.getInputStream()));
             PrintWriter cOut = new PrintWriter(client.getOutputStream(), true)) {

            // Formato richiesta al Gateway: "<serviceName> <payload>" (es. "inventory CHECK_ITEM_99")
            String req = cIn.readLine();
            if (req == null) return;
            String[] parts = req.split(" ", 2);
            String targetService = parts[0];
            String payload = parts.length > 1 ? parts[1] : "STATUS";

            // 1. Chiede al ServiceRegistry (:9000) gli endpoint disponibili
            String discovered;
            try (Socket reg = new Socket("127.0.0.1", 9000);
                 PrintWriter rOut = new PrintWriter(reg.getOutputStream(), true);
                 BufferedReader rIn = new BufferedReader(new InputStreamReader(reg.getInputStream()))) {
                rOut.println("DISCOVER " + targetService);
                discovered = rIn.readLine();
            }

            if (discovered == null || discovered.startsWith("404")) {
                cOut.println("{\"error\":\"503 Service Unavailable\",\"service\":\"" + targetService + "\"}");
                return;
            }

            // 2. Load Balancing Round-Robin con Failover automatico se un nodo è caduto!
            String[] instances = discovered.split(",");
            int startIdx = Math.abs(rrCounter.getAndIncrement());

            for (int i = 0; i < instances.length; i++) {
                String endpoint = instances[(startIdx + i) % instances.length];
                String[] hp = endpoint.split(":");
                try (Socket backend = new Socket()) {
                    backend.connect(new InetSocketAddress(hp[0], Integer.parseInt(hp[1])), 1500);
                    backend.setSoTimeout(2000); // Timeout Circuit Breaker!

                    PrintWriter bOut = new PrintWriter(backend.getOutputStream(), true);
                    BufferedReader bIn = new BufferedReader(new InputStreamReader(backend.getInputStream()));
                    bOut.println(payload);
                    cOut.println(bIn.readLine());
                    return; // Risposta inoltrata con successo!
                } catch (IOException failedNode) {
                    System.err.println("[Gateway] Nodo " + endpoint + " non risponde, provo replica successiva...");
                }
            }
            cOut.println("{\"error\":\"502 Bad Gateway - Tutte le repliche sono irraggiungibili\"}");
        } catch (IOException ignored) {}
    }
}

Traccia: Nel codice di ServiceRegistry sopra, se un microservizio viene spento improvvisamente, il suo indirizzo rimane registrato nella ConcurrentHashMap.
Aggiungi al ServiceRegistry un Health-Checker periodico in background usando ScheduledExecutorService che ogni 5 secondi:
1. Scorra tutti i servizi e i relativi endpoint host:port registrati.
2. Apra un Socket con timeout di 1000 ms, invii "PING" e verifichi che la risposta sia "PONG".
3. Se il nodo non risponde o va in timeout, lo rimuova automaticamente dalla CopyOnWriteArrayList stampando "[HealthCheck] Rimosso nodo inattivo: " + endpoint!

Suggerimento: Poiché nel ServiceRegistry abbiamo usato CopyOnWriteArrayList<String>, puoi iterare in totale sicurezza sugli endpoint e chiamare endpoints.remove(endpoint) senza mai sollevare ConcurrentModificationException!

Soluzione Capstone: ActiveHealthChecker per ServiceRegistry.javaScheduledExecutorService + Socket Timeout
// Da aggiungere all'avvio di ServiceRegistry.main():
ScheduledExecutorService healthScheduler = Executors.newSingleThreadScheduledExecutor();

healthScheduler.scheduleAtFixedRate(() -> {
    registry.forEach((serviceName, endpoints) -> {
        for (String ep : endpoints) {
            String[] hp = ep.split(":");
            boolean alive = false;

            try (Socket probe = new Socket()) {
                probe.connect(new InetSocketAddress(hp[0], Integer.parseInt(hp[1])), 1000);
                probe.setSoTimeout(1000);

                PrintWriter out = new PrintWriter(probe.getOutputStream(), true);
                BufferedReader in = new BufferedReader(new InputStreamReader(probe.getInputStream()));
                out.println("PING");
                alive = "PONG".equals(in.readLine());
            } catch (IOException e) {
                alive = false;
            }

            if (!alive) {
                endpoints.remove(ep);
                System.out.println("[HealthCheck] Rimosso nodo inattivo per " + serviceName + ": " + ep);
            }
        }
    });
}, 5, 5, TimeUnit.SECONDS);

1. Creare e Avviare un Thread in Java (Runnable vs Thread)

In Java è buona pratica separare il compito da svolgere (interfaccia funzionale Runnable con l'unico metodo public void run()) dal gestore del flusso di esecuzione (classe Thread). In questo modo la tua classe può estendere un'altra superclasse ed essere passata a un ExecutorService.

Sintassi: 3 modi per avviare un Thread Worker su un SocketJava 8 - 21+
// MODO A: Classe esplicita che implementa Runnable (Ideale per passare il Socket nel costruttore)
public class ClientWorker implements Runnable {
    private final Socket client;
    public ClientWorker(Socket client) { this.client = client; }

    @Override
    public void run() {
        System.out.println("Eseguito da: " + Thread.currentThread().getName());
    }
}
// Avvio reale in parallelo (NON chiamare .run() direttamente!):
Thread t = new Thread(new ClientWorker(socket), "Worker-1");
t.start();

// MODO B: Lambda Expression (Java 8+, dato che Runnable è @FunctionalInterface)
new Thread(() -> gestisciConnessione(socket)).start();

2. Ciclo di Vita del Thread e Blocchi di Rete

  • NEW: Oggetto new Thread(...) creato, ma start() non è ancora stato chiamato.
  • RUNNABLE: Il thread è pronto o in esecuzione sulla CPU. Quando chiama server.accept() o in.readLine(), il Sistema Operativo lo sospende in attesa dei dati dalla scheda di rete senza consumare cicli CPU!
  • WAITING / TIMED_WAITING: In attesa di un altro thread (es. t.join(), Thread.sleep(1000) o socket.setSoTimeout(3000)).
  • TERMINATED: Il metodo run() è terminato (normalmente o per eccezione). Un thread terminato non può essere riavviato!

// Se un thread è bloccato su serverSocket.accept() o socket.getInputStream().read(),

serverSocket.close(); // Sblocca accept() sollevando SocketException nel thread in ascolto!

3. Race Condition, synchronized e Strutture Dati Concorrenti

In un Server Multithread, ogni variabile locale dentro run() è privata del singolo thread (sicura!), ma i campi statici o gli oggetti passati a tutti i ClientHandler sono condivisi in memoria Heap.

// ❌ VIETATO in un Server Multithread (causano corruzione dati o cicli infiniti):
// HashMap, ArrayList, HashSet, contatori int++ non sincronizzati

// ✅ CORRETTO per Mappe condivise (es. Utenti connessi, Prodotti, Service Registry):
ConcurrentHashMap<String, PrintWriter> clientConnessi = new ConcurrentHashMap<>();

// ✅ CORRETTO per Liste lette spesso e modificate raramente (es. Lista di repliche o Chat):
CopyOnWriteArrayList<String> nodiAttivi = new CopyOnWriteArrayList<>();

// ✅ CORRETTO per Contatori (es. ID ordine progressivo, indice Round-Robin Load Balancer):
AtomicInteger idOrdine = new AtomicInteger(1000);
int nuovoId = idOrdine.incrementAndGet();

// ✅ CORRETTO per Operazioni Composte (Check-Then-Act su più variabili):
public synchronized boolean prelevaDalConto(double importo) {
    if (saldo >= importo) {
        saldo -= importo;
        return true;
    }
    return false;
}
